# Paint layers marked and cropped in the native format

Status: Proposed. The owner decides whether it is accepted.

## Context

The Brush and the Eraser paint on an image layer. A stroke on an empty page made a paint
layer as large as the page, which stored the whole page as pixels whatever was painted,
lost the pixels of a stroke that went past the page, and could not be told apart from a
placed picture, whose frame must never change.

## Decision

Let an image layer of native format 2 carry an optional `paintLayer` field whose only
value is `true`.

- The Brush makes paint layers with the field; placed pictures never carry it.
- While a stroke runs, a paint layer is drawn in a frame on the page axes that covers the
  page and the layer, so a stroke can reach the whole page and keep what lies outside it.
- When the stroke ends, the layer is cropped to the pixels that are not transparent, keeping
  each painted pixel where it was; a layer erased completely is removed. A stroke that
  changes nothing leaves no undo step, and a result beyond the limits of the document is
  refused whole, leaving the document as it was.
- The editor and the API validate the field alike: `true` on an image layer only, never
  null, and only in format 2.

## Consequences

Paint layers keep only what was painted, so projects are smaller and a paint layer can be
moved, turned and reflected like any object; a turned or reflected paint layer is baked
upright on the next stroke without moving its pixels. Earlier editors and APIs refuse
documents that carry the field; the release note says so, and the migration is to keep a
copy. Placed pictures behave as before. Nothing new is fetched or executed, and no
dependency is added.

## Alternatives considered

- Telling paint layers apart by their name. A name can be changed by the user, so it
  cannot decide whether a frame may be cropped.
- Cropping every image layer. It would change the frame of placed pictures, which must
  keep the size they were placed at.
