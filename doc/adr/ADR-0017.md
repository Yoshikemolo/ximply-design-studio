# ADR-0017 — Strict quality gate across every module

Status: Proposed
Date: 2026-09-19
Owner and reviewer: Yoshikemolo

## Context and problem
The owner requires tighter quality thresholds than the source methodology examples.

## Proposed decision
Enforce zero bugs/vulnerabilities/smells/hotspots, coverage >80 and duplication <3 on whole/new code; no missing evidence pass.

## Alternatives considered
Using default gate or reviewed hotspots can pass while violating the explicit request.

## Decision drivers and consequences
Collector/metric-version validation and module-level checks; empty design cannot claim product quality.

## Security impact
Enforce the related SEC constraints at the authoritative boundary; document and test
new trust crossings. No client or plugin UI condition substitutes for authorization.

## Operational and performance impact
Benchmark this boundary with the fixed fixtures before claiming production capacity.
Record dependencies, failure handling, resource ownership and release compatibility.

## Migration impact
Version affected contracts and stored payloads. Existing documents and settings must
remain recoverable; no silent destructive migration or unrecorded format conversion.

## Observability and verification
Boundary-value verifier tests and fresh per-module analysis tied to commit.
Record source revision, runtime, trace/correlation IDs and safe diagnostics.

## Superseded decisions
None. This proposal has not been accepted by an agent.
