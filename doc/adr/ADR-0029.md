# Declarative procedural floor-plan geometry

Status: Proposed; preview implementation does not constitute acceptance.

## Proposed decision

Extend native-v2 vector layers with optional declarative procedural metadata.
Resolve a bounded wall/door/window/pillar key through a trusted local geometry
registry. Documents contain parameters and references, never executable functions.
Derive display/export contours from this source of truth instead of destructively
replacing parametric objects with the latest generated paths.

Retain wall source identities while composing visible intersections and shared end
faces. Join only matching styles and group membership inside compatible stack runs;
openings may intervene, but ordinary artwork and incompatible walls are boundaries.
Apply a visible opening cutout to its own host before union, preserving other walls.
Derive wall-normal physical thickness under shear and share resulting geometry in
Canvas and SVG. Model a hosted
opening with an explicit wall reference and bounded placement parameters. Validate
references and parameter shapes in both the native parser and authenticated API.
Use shared geometry for editor rendering and export, and integrate parameter changes
with the existing history boundary. Avoid introducing a separate BIM graph, runtime
plugin loader, transport or third-party dependency in this preview.

## Consequences and migration

Parametric metadata and host relationships require compatible native-v2 readers.
Migration: preserve original files and use this version or newer for new saves.
Rendered exports preserve visible geometry but not the native procedural contract.
Removing procedural support does not migrate existing files backwards.

Geometry generation, host lookup and intersection work require explicit bounds.
Deletion, duplication and transformations must preserve or deliberately remove host
relationships rather than leaving stale IDs. This is a two-dimensional vector-plan
model; it does not establish building-code compliance, solid walls, persistent
architectural constraints or BIM interoperability. Final acceptance remains human.
