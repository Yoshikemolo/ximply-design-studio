# Editable vector blends with materialized intermediate objects

Status: Proposed; preview implementation does not constitute acceptance.

## Proposed decision

Represent a blend with optional native-v2 document metadata referencing two ordered
sets of endpoint layers, intermediate layer IDs, a group identity, step count and
easing. Intermediate objects remain ordinary vector layers, sharing existing
renderer and export paths. Treat generated geometry as a derived cache that updates
from endpoint edits and can normalize on load after strict reference validation.

Interpolate paired compatible vector contours, using exact subdivision to equalize
bounded vertex counts and premultiplied RGBA for colors including absent paint.
Continuous geometry and style values interpolate; discrete style enums select an
endpoint value. Group pairs use stable stacking order and equal leaf cardinality.
Reject unsupported geometry explicitly rather than silently producing unrelated
shapes. Keep existing document layer and group-depth limits; no new dependency.

Keep original endpoint IDs. Nested groups must retain common parent ownership.
Expand removes the live relation while retaining all objects; release removes
intermediate layers while retaining endpoints. Ungroup expands before releasing
group structure. History captures the entire operation. Duplicate and structural
edits must not leave dangling references or accidentally share live endpoints.

## Consequences and migration

Editable blend metadata requires updated readers. Preserve original documents.
Rendered exports retain visible intermediate objects but not editable blend links.
Only compatible vectors are supported; text, images, spine editing and path-following
orientation remain outside this preview. Preview test evidence does not authorize
integration without existing quality gates and review.
