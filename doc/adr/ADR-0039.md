# Git operations executed by the API service

Status: Proposed on 2026-09-23. Not accepted; an agent drafted it for the owner's review.

## Context

FEAT-0031 needs commit, branch, checkout, merge, fetch, pull, push, history and undo
from the editor, centralized like the other actions of the tool. A browser cannot run
Git on a local directory, and repository operations touch the file system and remote
credentials, so they belong behind the authenticated API service.

## Proposed decision

- New endpoints of the existing FastAPI service under `/api/vcs` expose a closed set of
  operations: status, log with graph data, show commit, commit, branch create, rename
  and delete, checkout, merge, merge abort, conflict resolution by side, fetch, pull,
  push, revert, and undo and redo of the last operations. There is no endpoint that
  accepts free Git arguments.
- The service runs the Git command line installed on the host, pinned to a minimum
  version, as a subprocess with an argument list (never a shell), a fixed working
  directory inside the workspace root, `--` before paths, validated reference names,
  hooks disabled, an isolated configuration that ignores the repository's own
  executable settings, and a timeout per operation.
- Operations on one repository are serialized by a lock; long operations run off the
  request event loop.
- The service keeps an operation journal per repository with the references before and
  after each operation, which defines undo and redo (FEAT-0031) and is never pushed.
- The graph layout (lanes, edges) is computed in the domain package from commit and
  parent data, so it is testable without Git.
- The UI talks to a change-control facade; a real adapter calls `/api/vcs` and a mock
  adapter for development shares the same contract suite and is visibly marked.

## Alternatives

- A pure Python Git library such as dulwich. No external binary, but merge and remote
  support is narrower and behaviour differs from the command line users know.
- libgit2 bindings (pygit2). Complete, but adds a native dependency to build and ship.
- The GitHub REST API only. It cannot work on local repositories or offline, and turns
  every commit into remote calls.

## Consequences

Git becomes a runtime requirement of the host when change control is enabled; the
service reports its absence or an old version as a capability state. The feature is
unavailable when the API service is not running.

## Security, operations and performance

See SEC-0013: path confinement, option injection, hooks and repository configuration,
credential isolation and output validation. Operation timeouts and repository size
limits are recorded in the plan.

## Migration and observability

No stored format change beyond ADR-0038. Traces carry the operation name, repository
identifier and duration, never file content or credentials.

## Verification

SC-0125 to SC-0133 against fixture repositories built by scripts, and adversarial tests
of SC-0132.
