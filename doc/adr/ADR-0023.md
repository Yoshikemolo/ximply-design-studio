# ADR-0023 — Editable cubic drawing and bounded polygon erasure

Status: Proposed. Human acceptance pending.

## Context

Drawing operations need one editable geometry representation shared by selection,
rendering, native persistence and export. Filled-vector erasing also needs robust
polygon difference without silently converting artwork into pixels.

## Proposed decision

Represent cubic controls and compound subpaths in native format 2 while importing
format 1. Keep geometry in the framework-free domain package. Use polygon-clipping
0.15.7, exact-pinned with the lockfile, for filled-region difference. The package is
MIT-licensed; retain its applicable license notices in distributions. This dependency
is a bounded implementation choice, not acceptance of a general geometry kernel.

Sample each curved segment at 24 steps before polygon difference. Return editable
vector output and expose the approximation in release notes and the roadmap. Raster
tracing similarly remains a bounded scanline implementation at 64 pixels per side.
Do not claim exact curve booleans or production contour tracing.

## Alternatives and consequences

An exact cubic intersection kernel offers better curve fidelity but requires separate
robustness and performance evidence. Raster erasing avoids polygon topology but loses
editable vector output. A home-grown polygon difference engine expands maintenance
and numerical-risk scope. The selected dependency introduces transitive supply-chain,
license and numerical-degeneracy review obligations; pinning alone does not close them.

## Security, verification and performance

Validate finite coordinates, allowed document versions and bounded geometry before
operations. Test empty intersections, holes, disjoint regions, touching edges and
undo/native round trips. Review dependency advisories and distribution notices before
integration. Measure worst-case brush and polygon workloads; do not infer a performance
budget from simple examples. Full static/security analysis remains required.

## Migration and rollback

Save new documents as version 2; read version 1 without modifying the original file.
Old applications cannot open v2. Preserve originals and explain that source rollback
does not reverse document upgrades. Revisit this decision if exact curve preservation
or production geometry workloads exceed the bounded approach.

## Supersedes

None. Extends the proposed geometry direction in ADR-0010 without accepting it.
