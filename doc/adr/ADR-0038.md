# Project directory as a diff-friendly versioned tree

Status: Proposed on 2026-09-23. Not accepted; an agent drafted it for the owner's review.

## Context

Today a project is one native JSON document, and placed pictures and paint layers are
carried inline as encoded image data. FEAT-0031 versions a project with Git and lets
several people merge their work. The owner expects a project to be larger than the
single project file. Inline pixels make every commit carry whole images and make diffs
unreadable; unstable key order would turn a small edit into a large change. ADR-0009
proposes a ZIP archive, which Git cannot diff or merge.

## Proposed decision

- A project is a directory with a manifest file, a `documents/` folder holding one or
  more native documents, and a `resources/` folder holding pixel and font resources as
  files named by the hash of their content.
- Documents in a project directory are written in a canonical form: stable key order,
  one object per line group, fixed number formatting and a trailing newline, so that
  saving an unchanged document changes no byte.
- Image layers in a project directory reference a resource by hash instead of carrying
  inline data. The editor and the API validate the reference and the resource with the
  same checks as inline images.
- A `.gitattributes` file created with the project marks resources as binary.
- The single-file native format keeps working unchanged; converting a document to a
  project directory, and exporting a project back to a single file, are explicit
  actions. The ZIP archive of ADR-0009 stays the portable exchange form.

## Alternatives

- Committing the current single JSON file. It works but every image change rewrites the
  file, and history grows with every pixel edit.
- Committing the ZIP archive. Git cannot diff or merge it.
- Git large-file storage for resources. It adds a server requirement; it can be added
  later for resources without changing this layout.

## Consequences

A new native format version adds resource references; earlier editors and APIs refuse
documents that carry them, and the release note must say so. The project manifest gets
a schema in `contracts/`. The API repository adapter gains a directory mode.

## Security, operations and performance

Resource paths are derived from hashes only, never from document text. Project files
from a remote are untrusted and validated before use (SEC-0005, SEC-0013).

## Migration and observability

Existing single-file documents open as before. Conversion is explicit and reversible by
exporting a single file. Migration fixtures cover documents with inline images.

## Verification

SC-0127 for canonical saving and resources; format validation tests in the editor and
the API; round trip of single file to project directory to single file.

## Supersedes / references

None superseded. Complements ADR-0009 and ADR-0011.
