# Bounded in-process parsing of imported interchange formats

Status: Proposed; the preview implementation of the text formats does not constitute
acceptance, and the deferred formats are not authorized by this record.

## Context

The import action accepts PNG, JPEG and WebP only. The owner asked for SVG,
Illustrator, DXF, DWG, Canva and PDF as well. These formats differ in kind: two are
text formats a bounded parser can read, two are documented binary containers that
need a third-party runtime, one is proprietary with no open specification, and one is
not a file format at all.

## Proposed decision

Read imported files as untrusted data with parsers that live in the domain package,
own no input beyond the bytes given to them and reach no network. Accept the text
formats in this slice and decide the rest separately.

- SVG and ASCII DXF are parsed by our own bounded readers. They use no third-party
  parser, expand no entities, resolve no external references, execute nothing and
  stop at explicit element, node and size limits. Their output is ordinary native
  layers, so an import is indistinguishable from drawn artwork once accepted.
- PDF, and therefore modern Illustrator files, which are PDF containers, are read by
  the same kind of bounded reader rather than by a parser of the size of pdf.js. It
  walks the indirect objects it can see, takes the first page and interprets the
  drawing operators of its content stream into native paths; it follows no reference
  outside the file, runs no JavaScript the file may carry and resolves no encryption.
  Stream decompression uses the decompression the browser already provides, so no
  dependency is added. Text, placed objects, inline images, gradients and clipping
  paths are reported rather than approximated, and an encrypted or otherwise
  unreadable file is refused with an explanation.
- DWG has no open specification and no maintained parser that can run in the browser
  under a compatible licence. It is refused with an explanation that points at DXF,
  which every DWG authoring tool exports.
- Canva is a hosted service, not a file format. Its designs leave as SVG, PDF or PNG,
  which the rules above already cover. An account integration is a different subject
  with its own authorization and privacy record.

## Consequences

The editor gains real vector interchange without a new runtime, Illustrator files
included, at the cost of representing only what the page draws: an imported drawing
carries geometry and flat colour, not layers, effects or editable text. What a reader cannot
represent is reported to the person instead of being dropped silently, so an import
never pretends to be complete. The deferred formats stay explicitly unsupported in
the interface rather than appearing as failing actions. Accepting PDF later does not
invalidate this record; it extends it.

## Alternatives considered

Parsing SVG with the browser DOM parser would be less code, but it would put document
parsing in the interface layer, tie the domain to a browser global and inherit the
entity and external-reference behaviour of a general XML parser. Shipping a converter
service for DWG was rejected for this slice: it moves private drawings to a process
the owner has not authorized.

## Security and validation

Imported text is data, never instructions. Scripts, event handlers, external
references, embedded stylesheets and document type declarations are ignored or
rejected. Sizes, element counts and numeric ranges are bounded before layers are
created, and every produced layer goes through the native validator before it enters
a document. Oracles: [SC-0091](../sc/SC-0091.md), [SC-0092](../sc/SC-0092.md) and
[SC-0097](../sc/SC-0097.md).
