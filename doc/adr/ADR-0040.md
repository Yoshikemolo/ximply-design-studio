# GitHub remote credentials held by the API service

Status: Proposed on 2026-09-23. Not accepted; an agent drafted it for the owner's review.
It introduces an authentication method, which AGENTS.md reserves for a reviewed ADR.

## Context

Pull and push to a shared GitHub repository need a credential per user. The editor runs
as a local preview with one API user today; the owner wants several users to work on a
shared repository from their own installations.

## Proposed decision

- First slice: each user enters a GitHub fine-grained personal access token limited to
  the project repository with contents read and write. The API service stores it outside
  repositories and documents, readable only by the service account, and passes it to Git
  for one operation through a credential helper, never in a remote URL, configuration
  file, command line argument or log.
- The token is never returned to the browser. Settings shows only whether a token is
  configured, its repository scope and a connection test.
- Later slice, subject to its own acceptance: sign-in with a GitHub App through the
  device authorization flow, giving short-lived user tokens without copying a token.

## Alternatives

- SSH keys. They need key management on each host and are outside the first slice.
- The GitHub App device flow first. Better for many users, but it requires registering
  and operating an app before anyone can try the feature.
- Classic personal access tokens. Their scopes cover every repository of the account.

## Consequences

Users create and rotate their own token; the documentation of the feature explains the
minimal permissions. Remotes other than GitHub are out of scope until another decision.

## Security, operations and performance

See SEC-0013. Stored tokens are removable from Settings and are never exported with a
project. Authentication failures are reported without echoing the token.

## Migration and observability

No format change. Audit records keep the operation, remote host and result, never the
token.

## Verification

SC-0130 and the secrecy oracle of SC-0132.

## Supersedes / references

None superseded. Related to ADR-0012 for the product's own identity model, which this
decision does not replace.
