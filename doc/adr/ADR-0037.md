# External agent provider called through the API service

Status: Accepted by the owner, Yoshikemolo, on 2026-09-23, with one provider key per
installation. Using the capability also requires sign-in and a licence with the AI Tools
permission (ADR-0041).

## Context

FEAT-0029 sends document context, images and a prompt to an external agentic model and
receives changes to apply. The first provider requested is OpenAI through its API. This
is a new trust crossing: private document content and pixels leave the machine, a
secret key is needed, and the answer is untrusted content that asks to change the
document. The architecture forbids logging prompts, pixels or tokens and requires that
content never grants permissions (SEC-0004).

## Proposed decision

- The browser never calls the provider. The AI Tools facade calls new endpoints of the
  existing FastAPI service under `/api/ai`, and a provider adapter in that service calls
  the provider over HTTPS. No new runtime or transport is introduced; the adapter adds
  one pinned HTTP client dependency or the provider's official Python SDK, to be chosen
  in the implementation plan and recorded in the dependency register.
- The API key is stored by the API service, outside documents and repositories, readable
  only by the service account, and never returned to the browser. The first slice keeps
  one key per local installation.
- The provider is asked to answer only through a fixed catalogue of operations defined
  by a versioned JSON schema in `contracts/`, using the provider's structured output or
  tool calling, plus generated images when the operation catalogue asks for one.
- The API service validates every operation against the schema, the permitted scope
  sent with the request, document limits and the image checks of SEC-0005 before the
  browser shows a proposal. The editor applies accepted operations through its ordinary
  commands, so undo, validation and saving are unchanged.
- The adapter port has a real implementation and a contract-test double sharing one
  contract suite. There is no silent fallback to the double or to another provider.
- Where the provider offers it, requests ask it not to retain the request; the owner
  reviews the provider's data terms before the capability is enabled for real content.

## Amendment of 2026-09-24

Accepted by the owner, Yoshikemolo, on 2026-09-24: the provider token belongs to each user,
not to the installation. A user with the agent tools permission, or the super
administrator, enters their own OpenAI API token in Settings > External tokens. The API
service stores it encrypted at rest with a service key (`XDS_TOKEN_KEY`), tied to the
verified subject, uses it only for that user's requests, and never returns it; without the
service key it refuses to store tokens. Requests to the provider are made with the token of
the user who sends them.

## Alternatives

- Calling the provider from the browser. It exposes the key to the page and to
  extensions and bypasses server-side validation and audit.
- Letting the model issue arbitrary editor commands or scripts. It grants authority the
  designer cannot review and breaks SEC-0004.
- Waiting for the MCP bridge of FEAT-0019. It delays the requested capability; the
  operation catalogue proposed here can later be exposed through MCP unchanged.

## Consequences

The capability needs the API service to be running and reachable; without it the panel
states that AI Tools are unavailable. Adding another provider means another adapter
behind the same port. Costs and rate limits of the provider apply to the owner's key.

## Security, operations and performance

New egress to the provider's HTTPS endpoint only. Request size, timeout and concurrent
requests are bounded. Audit records keep metadata and digests, never prompt text,
pixels or the key. See SEC-0012.

## Migration and observability

No document format change: applied results are ordinary layers. The proposal schema is
versioned; answers with an unknown version are refused. Traces carry a correlation ID
from the panel to the provider call.

## Verification

SC-0118 to SC-0122, contract tests of the adapter port, and adversarial tests with
injected permission text and out-of-scope operations.

## Supersedes / references

None superseded. Related to ADR-0015, which remains the decision for the MCP bridge.
