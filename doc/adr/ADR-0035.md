# Gradient meshes carried by path layers in the native format

Status: Proposed. The owner decides whether it is accepted.

## Context

Illustrator's Mesh tool turns an object into a mesh whose points carry colours that blend
across it, and Object > Create Gradient Mesh does so with a regular grid. The native format
had no object that holds colours at the points of a mesh.

## Decision

Let a path layer of native format 2 carry an optional `gradientMesh` field, as it carries
an envelope (ADR-0034).

- The field holds `mesh`, the same grid of Coons patches an envelope uses, in the layer's
  own coordinates, and `colors`, one colour per mesh point in six or eight hexadecimal
  digits, `none` excluded.
- The mesh is the object's outline: the layer has no curves or points of its own, and no
  envelope, brush, dimension, generated object, guide, symbol, fill paint or line endings.
- Across each patch the colour is the blend of its four corners by where a point lies in the
  patch. The canvas and SVG draw it as small facets; PDF draws it as a Coons patch mesh
  shading, which interpolates the same way.
- The editor and the API validate the field alike.

## Consequences

Gradient meshes stay editable across sessions: points can be added, removed, moved and
recoloured. Earlier editors and APIs refuse documents with a gradient mesh; the release
note says so, and the migration is to keep a copy or remove the meshes first. SVG carries
the mesh as many small polygons rather than a mesh gradient, which browsers do not draw.
Nothing new is fetched or executed, and no dependency is added.

## Alternatives considered

- A raster picture of the mesh. It would need no format change, but the mesh could no
  longer be edited, and it would not scale.
- The mesh gradient element of SVG 2 as the stored form. Browsers do not draw it, and it
  would tie the native format to an export format.
