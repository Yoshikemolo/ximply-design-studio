# SC-0132 — Confined repository operations and secret credentials

Status: Implementing
Feature: FEAT-0031
Owner: Yoshikemolo

## Injection oracle

Branch names, commit messages, remote URLs and paths that carry option text such as
--upload-pack, shell metacharacters, or traversal such as ../ are refused or passed as
data; no request runs a command or reads or writes a file outside the project directory.

## Hook and content oracle

Repository hooks and configuration from a cloned remote are not executed. Documents from
a remote are validated by the native document checks before the editor opens them.

## Secrecy oracle

After a GitHub credential is stored, no API response, log line, repository
configuration, remote URL, commit or exported file contains it.

## Evidence

Implemented for the local runner: argument lists without a shell, validated project identifiers and reference names that can never become options, hooks disabled, system and global configuration ignored, no prompts, a timeout and a lock per project. No remote credentials exist in this slice. Automated: services/api/tests/test_vcs.py (reference names never become options or paths, unknown projects refused, resources checked against their name) on feat/change-control for 0.13.0. Human review, a security review of the Git runner and the paused Sonar analysis are outstanding.
