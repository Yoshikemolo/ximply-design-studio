# SC-0131 — Undo and redo of Git operations

Status: Implementing
Feature: FEAT-0031
Owner: Yoshikemolo

## Inverse oracle

Undo of a commit moves the branch to its parent and keeps the changes as uncommitted; undo
of a checkout returns to the previous reference; undo of a branch creation deletes it;
undo of a branch deletion recreates it at its last SHA; undo of a local merge returns to
the state before it. Redo reapplies each operation with the same resulting SHAs.

## Boundary oracle

An operation whose commits were already pushed is not undone and a revert is offered.
Git undo and redo never change the document undo history, and document undo never
changes the repository.

## Evidence

Implemented through a journal of reference snapshots per clone; undoing is refused for commits already in the shared repository, with revert offered. Automated: services/api/tests/test_vcs.py (undo and redo follow the journal and spare shared commits) and apps/web/tests/change-control.test.ts (a commit undone keeps the document) on feat/change-control for 0.13.0. Human review, a security review of the Git runner and the paused Sonar analysis are outstanding.
