# SC-0157 — Bitmap or vector result

Status: Implementing
Feature: FEAT-0029
Owner: Yoshikemolo

## Choice oracle

The prompt controls offer Result: Bitmap or Vector. Bitmap sends the request to the image
model and inserts a picture. Vector sends it to the model with image input that answers in
text, with the selection, or the whole document, also exported as SVG framed on its bounds, and
inserts the answer as editable paths and groups. Convert to paths and groups always asks for a
vector result. A saved prompt remembers its result type.

## Drawing rules oracle

A vector request gives the model fixed drawing rules: exactly one standalone SVG, a viewBox,
`<g>` groups per logical part with descriptive ids, basic shapes and Bezier paths, solid
`#rrggbb` colours with gradients only where essential, no images, text, foreign objects,
scripts, styles, filters, masks, clip paths or external references, elements from back to
front, and, when a source SVG is given, the elements, ids and colours the instruction does not
concern kept as they are. When the model refuses a temperature, the request is sent again
without one.

## Picture lock oracle

When the context holds a visible picture, Vector and Convert to paths and groups are locked and
the panel says that vectors from pictures would mean tracing them, which a later version may
offer (owner decision of 2026-09-24). The API also refuses a vector request whose selection data
declares a picture.

## Evidence

Automated: services/api/tests/test_agent_tools.py (vector result with the rules and the source,
bitmap result, refusal for pictures, retry without temperature),
packages/domain/tests/agent-result.test.ts (vector context), packages/domain/tests/agent-prompts.test.ts
(locks vector results) and apps/web/tests/agent-tools.test.ts (bitmap or vector result), on
feat/vector-results for 0.13.3. Headless Chrome on the live stack showed the Result control and
the prompt search. A vector request against the live provider, human review and the paused Sonar
analysis are outstanding.
