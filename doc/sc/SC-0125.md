# SC-0125 — Change control settings and repository setup

Status: Implementing
Feature: FEAT-0031
Owner: Yoshikemolo

## Settings oracle

Settings lists a Change control category in the left column and shows only its form in
the right column. With change control disabled, the History tab explains how to enable it
and offers no operation, and the facade makes no change-control request.

## Setup oracle

Initializing a project directory inside the workspace root creates a repository with the
configured default branch, the project manifest and an initial commit by the configured
author. Opening an existing repository shows its current branch and history.

## Confinement oracle

A project directory outside the workspace root, or one reached through a symbolic link
that leaves it, is refused.

## Evidence

Partly implemented: a project is made from the open document, or opened from the list, in the History tab; the repository is created on the server with a first commit. The Settings > Change control category (enable switch, directory, author, remote, strategy) is not implemented: the author comes from the signed-in identity. Automated: services/api/tests/test_vcs.py (a project is a repository with a canonical document, access needs the licence) and apps/web/tests/change-control.test.ts (projects and commits) on feat/change-control for 0.13.0. Human review, a security review of the Git runner and the paused Sonar analysis are outstanding.
