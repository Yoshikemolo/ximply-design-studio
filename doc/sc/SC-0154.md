# SC-0154 — Provider requests through the API

Status: Implementing
Feature: FEAT-0029
Owner: Yoshikemolo

## Request oracle

`POST /api/ai/generate` requires a verified session whose licence includes `ai-tools`; it
validates the action, the scope, the creativity and each PNG (signature and 20 MB) before any
provider call, and answers 409 with the way to fix it when the user has no saved token.
Picture actions call the image edit endpoint with every image and a transparent background
where the action needs one; Convert to paths and groups calls the responses endpoint with a
temperature derived from the creativity. At most four requests run at once.

## Secrecy oracle

The user's own token is decrypted only for the call. The audit record keeps the action, the
scope, the sizes and the outcome, never the prompt or pixels. Provider failures are explained:
a refused token, an account without API credit (`insufficient_quota`), too many requests per
minute (`rate_limit_exceeded`), any other rate or quota limit with OpenAI's own message, a
refused request with its reason, and an unreachable provider. The connection test of Settings
only lists the models, which OpenAI allows without credit, so it cannot detect a missing
credit.

## Evidence

Automated: services/api/tests/test_agent_tools.py (access, validation, provider requests, failures, audit) on feat/agent-tools-panel for 0.12.0. Human review, a request against the live provider with the owner's token and the paused Sonar analysis are outstanding.
