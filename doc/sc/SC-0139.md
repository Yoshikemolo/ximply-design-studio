# SC-0139 — Keycloak unavailable or misconfigured

Status: Implementing
Feature: FEAT-0032
Owner: Yoshikemolo

## Unavailable oracle

With no Keycloak configured, the API reports demo mode and the header shows no Sign in
button but a note that advanced mode is not configured. With Keycloak unreachable, sign-in
reports it, the demo keeps working and advanced requests are refused; the API does not
fall back to any local licence.

## Secret oracle

The service account secret and the Keycloak admin password never appear in API
responses, the web bundle, logs or the repository; the realm file carries placeholders
only.

## Evidence

Automated, on the feat/sign-in-and-licences branch for 0.11.0: services/api/tests/test_identity.py
(token validation, forged and stale tokens, licence policy, super administrator, suspension),
services/api/tests/test_administration.py (users, passwords, bans and their lifting, roles,
licences with tier, state and period, documents and owners, self-protection, the Keycloak
adapter against a recorded exchange), services/api/tests/test_external_tokens.py (per-user
encrypted tokens), tests/test_local_launcher.py (identity secrets), apps/web/tests/session.test.ts
(PKCE, session, capabilities, administration calls and workspace) and
apps/web/tests/smart-table.test.ts (search, typed filters, sorting, paging, selection). Web
suite 1035 tests passed; API 129 passed, the two failures being the typography round trips
that fail the same way on dev under the local Python 3.14. End to end against a local
Keycloak 26.0.8 imported from infra/keycloak/xds-realm.json: PKCE sign-in, token claims,
issuing, extending and revoking licences, the administration workspace rendered with a real
administrator session in headless Chrome. Not verified: that the account console refuses a
user editing their own licence attribute, and any Keycloak on the published preview, which
has none. Human review and the paused Sonar analysis are outstanding.
