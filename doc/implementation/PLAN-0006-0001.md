# Document tabs, Clear and unsaved-change protection

## Problem and acceptance

New document and the tab strip plus button previously replaced the only open
document after a native browser prompt. The owner requires File > Clear with a
confirmation when the document has unsaved changes, and working New document and
new-tab actions. Oracle: [SC-0085](../sc/SC-0085.md).

- New document and the plus button open a blank document in a new active tab.
- Each tab keeps its own content, undo history and selection when switching.
- A tab shows an unsaved marker after an edit; save, open and Clear reset it.
- Clear empties the active document immediately when it is saved and asks first
  when it is not; Cancel or Escape keeps the content. Clear is undoable.
- Closing a tab with unsaved changes asks first; closing the last tab leaves one
  blank tab. Opening a project reuses an untouched blank tab.
- No native `confirm()` or `alert()` remains; the dialog is localized EN/ES.

## Scope and design

`EditorService` keeps the active document in its existing signals and parks
inactive tabs as snapshots `{document, history, dirty, selection}`. Dirty state
compares a document edit counter with the count at the last save, open or Clear;
redraw-only revisions do not count. The native file format is unchanged.

Local recovery moves from the single `xds-draft` key to `xds-workspace`
(index of tab ids, active id and unsaved flags) plus one `xds-workspace:<id>` key
per tab. The earlier draft is migrated once and marked unsaved when it has content.
Limits: 12 open tabs, 4 MB per stored document, tab ids must be UUIDs, each stored
document is parsed by the native validator and unreadable tabs are skipped.

Exclusions: per-tab zoom and scroll, tab reordering, closing several tabs at once,
and browser-level prompts when the page itself is closed.

## Security

Drafts stay in the browser origin's local storage, unencrypted, as before; nothing
is sent to a server. Restored content goes through `parseDocument`, the same
validator as opened files, so a tampered draft cannot inject unvalidated layers.
See [SEC-0010](../sec/SEC-0010.md) for the confidentiality boundary.

## Failure and migration

Migration: the first start of this version converts `xds-draft` into the workspace
format and removes the old key. Older previews do not read the new keys and start
blank; project files are unaffected. Storage quota errors leave the session running
and ask the user to save a project file.

## Validation and handoff

Tests: `apps/web/tests/document-tabs.test.ts` (service and confirmation flow) and
`apps/web/tests/shell-template.test.ts` (menu, tab strip, no native prompts).
Recorded in 0.4.0. Visual browser acceptance, strict Sonar evidence and
independent review remain outstanding.
