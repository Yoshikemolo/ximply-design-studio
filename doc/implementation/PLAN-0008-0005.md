# Drafting-rule presentation for linear dimensions

## Problem and acceptance

The linear dimension tool did not pre-mark snap points, drew an unbroken dimension
line with a free horizontal label and never moved arrows outside short spans.
Oracle: [SC-0086](../sc/SC-0086.md).

- Hovering with a dimension tool shows a small blue square on the snapped point:
  vertex, intersection, edge midpoint or a point on an edge, in that priority.
- The first two clicks fix the measured points; the third chooses the side and
  offset. After the second click the actual annotation previews under the cursor.
- The label is aligned with the dimension line, readable (never upside down), and
  interrupts the middle of the line when `label + 2 arrowheads + 2 arrowhead-sized
  clearances` fit between the extension lines.
- Otherwise the arrowheads point inward from outside, the dimension line extends
  beyond both extension lines, and the label sits beyond the end nearest to the
  placement point.
- Extension lines start a small gap from the measured points and overshoot the
  dimension line. Arrowheads use a 3:1 length to width ratio.

## Drafting rules applied

Sources: ISO 129-1 (extension gap and overshoot about 8 line widths, arrows outside
extension lines when space is limited), ASME Y14.2/Y14.5 practice (about 1.5 mm
visible gap, 2-3 mm overshoot, filled 3:1 arrowheads, value in a break of the
dimension line). New dimensions default to a 6 px gap and 8 px overshoot at 96 ppi.

## Scope and design

`dimensionGeometry(layer, measure?)` now also returns label angle, width, height and
placement. Canvas, SVG export, hit testing and the placement preview share it. The
native `dimension` object is unchanged; the stored label position is the placement
point, from which offset and side are derived. `lineEndGeometry` gains an optional
spread used only by dimensions. Angular dimensions keep their previous presentation.

The same slice removes the quick Fill, Stroke and Width rows from the tool rail; the
overlapping fill and stroke squares keep the full appearance picker.

## Failure and migration

Existing documents open unchanged but render with the new presentation: labels
follow the line direction and break it. No file migration is needed. Label frame
settings still apply. Exclusions: chained or baseline dimensions, tolerances,
radius and diameter dimensions, and associativity with the measured artwork.

## Validation and handoff

Tests: `packages/domain/tests/dimensions.test.ts` (independent geometric oracles for
each rule), `packages/renderer/tests/dimensions.test.ts`,
`apps/web/tests/dimensions-editor.test.ts`. Recorded in 0.3.15-alpha.1. Visual
browser acceptance, strict Sonar evidence and independent review remain outstanding.
