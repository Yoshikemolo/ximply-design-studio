# Revision-bound quality evidence collector

## Requirement and independent acceptance

FEAT-0023 / SC-0067 / SC-0068 require actual metrics from the expected revision,
not an earlier passing analysis. Preserve strict thresholds. Bind each module to
its submitted task, project, successful analysis ID and revision. Check latest
analysis before and after reading current measures to reject concurrent updates.
Negative fixtures cover stale/missing evidence, wrong projects, pending tasks,
non-finite values, transport redirects and unavailable metrics.

## Scope and boundaries

Python standard-library engineering harness only. No application architecture,
public API, database schema or dependency change. Support the Standard Experience
metric keys on explicitly version-pinned servers. First adapter collects main-project
analyses only; branch/PR analysis needs a separately validated adapter. Distinct
project keys may isolate trusted candidates; never silently request main measures
for a branch scan. No automatic Sonar provisioning or gate creation.

## Security and failure behavior

Read token from environment, never arguments or reports. Require HTTPS except
explicitly enabled literal loopback HTTP for local development. Reject redirects,
embedded credentials and server-address fields supplied by untrusted scan outputs.
Bound response size and timeout; redact transport/server exception content. Missing,
unknown or malformed data fails. No network retries hide pending/failed analysis.
Only write a complete report after all modules are collected; delete a prior output
before an attempted collection so an old pass cannot survive a failed run.

## Migration, rollback and limitations

Additive collector and manifest contract; existing normalized checker remains the
policy oracle. Include engineering code in the required module inventory rather
than excluding the harness. Roll back through a reviewed revert; never weaken the
quality policy to pass. Docker and a configured Sonar server are unavailable here,
so local tests do not count as live Sonar verification. Human review and live-server
contract validation remain required before integration or Verified status.
