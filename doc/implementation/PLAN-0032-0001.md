# Keycloak sign-in, licences and Admin menu

ID: PLAN-0032-0001
Status: Implementing
Owner: Yoshikemolo
Feature / scenarios / ADRs / SEC controls: FEAT-0032 / SC-0134 to SC-0139 / ADR-0012,
ADR-0041 / SEC-0014, SEC-0001, SEC-0002

## Problem and acceptance

Nobody can sign in, so no capability can be limited to licensed users, and the owner
cannot manage users or licences. Intended behaviour is recorded in FEAT-0032. Oracles:
SC-0134 to SC-0139, with tokens signed by a test key in API tests and a local Keycloak
for the end-to-end check.

## Scope and design

- Keycloak: a realm file in the repository (`infra/keycloak/xds-realm.json`) imported by
  the local compose: realm `xds`, public client `xds-studio` (code flow with PKCE S256,
  redirect to the local editor), bearer client `xds-api` with the client roles
  `ai-tools` and `change-control`, the realm role `xds-admin`, a confidential client
  `xds-admin-service` whose service account may only view and manage users, protocol
  mappers that put `xds_licence_expires` and the client roles in the access token, token
  lifetime of five minutes, and registration enabled.
- API service: token validation against the realm keys (a pinned JWT library, recorded
  in the dependency register), a licence policy as a pure function, a dependency that
  guards advanced endpoints, `GET /api/session`, and `GET/PUT/DELETE
  /api/admin/users[/{id}/licence]` through the service account, with an audit log.
  Configuration from environment variables; without them the service reports demo mode.
- Web: a session facade with a real Keycloak adapter (PKCE written with the Web Crypto
  API, no new runtime dependency) and a mock adapter for tests; Sign in and the user menu
  in the header; the Admin menu and its users dialog; capability states for advanced
  features; EN and ES catalogs; icons under /assets/icons.
- Contracts: `contracts/openapi.json` gains the session and admin endpoints.
- Excluded: the items listed in FEAT-0032.

## Extension of 2026-09-24

The owner asked for Keycloak pages branded with the studio logo, and for an
administration workspace that manages users, roles, licences and documents without
going to the Keycloak console (SC-0140 to SC-0146). Decisions taken for it, all within
ADR-0041:

- Login theme `xds` under `infra/keycloak/themes/xds`, extending Keycloak's `keycloak.v2`
  login theme with a template header and a stylesheet; the realm selects it.
- The service account additionally holds `view-events`; the realm stores login events
  for 90 days, which give the last sign-in.
- Bans disable the Keycloak account and record `xds_ban_until` (an instant, or
  `permanent`) and `xds_ban_reason`; the API lifts expired temporary bans on a
  one-minute schedule and whenever users are listed.
- A licence gains `xds_licence_issued` and `xds_licence_status` (`active` or
  `suspended`), carried in the token; a suspended licence is refused like an expired one.
- Documents saved by a signed-in user record the token subject as owner in the file
  store; the storage endpoints accept either the local API token, as today, or a valid
  session.
- The smart table gains optional global search, column filters, sorting, paging and
  row activation, keeping its current inputs so the export list is unchanged.
- The number of documents per user counts stored documents by owner.

## Delivered in 0.11.0 and further owner requests

- Dependencies pinned for the API: PyJWT 2.14.0 with cryptography 46.0.4, cffi 2.0.0 and
  pycparser 3.0, for token validation and the encryption of external tokens. The web client
  adds no dependency: PKCE uses the Web Crypto API. Keycloak 26.0.8 is pinned in the local
  compose file.
- Owner requests of 2026-09-24 delivered in the same block: the Demo or tier badge after the
  logo, tier colours shared by the badge and the tier columns, licence tiers Free, Pro, Teams,
  Studio and Enterprise that grant the same until limits are decided, the advanced tools
  block of the tool rail, the Properties, AI Tools and History tabs of the right column with
  the AI button of the header, Settings > External tokens with each user's own OpenAI API
  token (SC-0148), the administration workspace in the Settings layout with direct entries
  in the Admin menu, the side panel for forms, first-column selection with bulk actions,
  status icons, typed column filters, short dates with full ones on hover, ellipsis for long
  values and sort buttons in each heading.
- Local operation: `scripts/local.py start --identity` starts Keycloak; `reset-identity
  --confirm identity` imports the realm again; `scripts/live.py` serves the editor with hot
  reload at the usual address, http://localhost:8090, through the `live` profile.

Automated, on the feat/sign-in-and-licences branch for 0.11.0: services/api/tests/test_identity.py
(token validation, forged and stale tokens, licence policy, super administrator, suspension),
services/api/tests/test_administration.py (users, passwords, bans and their lifting, roles,
licences with tier, state and period, documents and owners, self-protection, the Keycloak
adapter against a recorded exchange), services/api/tests/test_external_tokens.py (per-user
encrypted tokens), tests/test_local_launcher.py (identity secrets), apps/web/tests/session.test.ts
(PKCE, session, capabilities, administration calls and workspace) and
apps/web/tests/smart-table.test.ts (search, typed filters, sorting, paging, selection). Web
suite 1035 tests passed; API 129 passed, the two failures being the typography round trips
that fail the same way on dev under the local Python 3.14. End to end against a local
Keycloak 26.0.8 imported from infra/keycloak/xds-realm.json: PKCE sign-in, token claims,
issuing, extending and revoking licences, the administration workspace rendered with a real
administrator session in headless Chrome. Not verified: that the account console refuses a
user editing their own licence attribute, and any Keycloak on the published preview, which
has none. Human review and the paused Sonar analysis are outstanding.

## Divergences from Illustrator

None apply; Illustrator CS3 has no accounts or licences.

## Work sequence

1. Licence policy and token validation in the API with signed test tokens (SC-0136).
2. Session endpoint and demo-mode reporting (SC-0134, SC-0139).
3. Admin endpoints over a Keycloak client port with a contract-tested fake (SC-0137,
   SC-0138).
4. Realm file and compose wiring; manual end-to-end check against local Keycloak.
5. Web session facade, PKCE flow and header (SC-0135), then the Admin menu (SC-0137,
   SC-0138), then capability states.
6. Documentation, operations notes, release notes and evidence.

## Failure and migration

No document format change. Without Keycloak configuration everything behaves as today.
A Keycloak outage disables advanced capabilities and admin actions only. Rollback is
removing the configuration; licences stay in Keycloak.

## Validation and handoff

API tests with signed tokens, web tests, documentation checks and a manual sign-in
against local Keycloak. Open questions for the owner: whether licences need a default
length when issued, and whether email verification is required at registration.
