# Change control with a Git history tab

ID: PLAN-0031-0001
Status: Proposed
Owner: Yoshikemolo
Feature / scenarios / ADRs / SEC controls: FEAT-0031 / SC-0125 to SC-0133 / ADR-0038,
ADR-0039, ADR-0040 / SEC-0013

## Problem and acceptance

A project has no version history, branches or way to share work between people beyond
copying files. Intended behaviour is recorded in FEAT-0031. Oracles: SC-0125 to SC-0133,
run against fixture repositories built by scripts with known topology and against a
disposable remote, never against a real user repository.

## Scope and design

- Domain: project manifest types, canonical document writer, commit graph lane layout,
  and the Git operation journal with its inverses, all without Angular or HTTP imports.
- Contracts: `contracts/project-manifest.schema.json`, the resource reference in
  `contracts/document.schema.json`, and new `/api/vcs` endpoints in
  `contracts/openapi.json`.
- API service: project directory repository adapter, Git runner with the confinement
  rules of SEC-0013, per-repository lock, credential helper and token storage.
- Web: change-control facade with real and mock adapters sharing a contract suite; the
  History tab with graph, details, bottom toolbar and node context menu; the Settings >
  Change control category; EN and ES catalogs; the project's own icons for commit,
  branch, merge, pull, push, fetch, checkout, undo and redo under /assets/icons.

## Divergences from Illustrator

Illustrator CS3 has no version control, so none apply and no shortcut is assigned. The
visual reference is a Git client in the style of GitKraken, used for layout only; no
third-party icon, name or branding is copied.

## Work sequence

1. ADR-0038 and ADR-0039 accepted on 2026-09-23; ADR-0040 revised to use Keycloak and
   awaiting acceptance before step 6. Deliver FEAT-0032 first.
2. Project directory format, canonical writer and conversion, with round-trip tests.
3. Git runner and `/api/vcs` status, log and commit with fixture repositories
   (SC-0125, SC-0127) and the adversarial tests of SC-0132.
4. Graph layout in the domain (SC-0126) and the History tab with details.
5. Branches and checkout (SC-0128), merges and conflicts (SC-0129), context menu
   (SC-0133), journal undo and redo (SC-0131).
6. GitHub remote, credentials and pull, push and fetch (SC-0130).
7. Settings category, documentation, threat model evidence and release notes.

## Failure and migration

A new native format version for resource references (ADR-0038); earlier editors refuse
it and the release note says so. Conversion to a project directory is explicit, and a
single file can always be exported back. Every failed operation leaves branches, files
and open documents unchanged. Rollback is disabling change control; repositories stay
valid Git repositories usable with any Git client.

## Validation and handoff

Domain, contract, API, integration and UI tests, documentation checks, a security review
of the Git runner, and the strict quality profile. Open questions for the owner: acceptance of the
revised ADR-0040; whether large-file storage is needed for
resources; the workspace root on the preview host; and whether object-level merging of
documents is required before multi-user use.
