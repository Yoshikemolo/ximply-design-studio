# Convert to pixel image as an Import image sub-tool

ID: PLAN-0030-0001
Status: Implementing
Owner: Yoshikemolo
Feature / scenarios / ADRs / SEC controls: FEAT-0030 / SC-0123, SC-0124 / ADR-0024,
ADR-0036 / SEC-0005

## Problem and acceptance

Vector art cannot be turned into pixels inside a document, and FEAT-0029 needs a
reliable picture of the canvas and of the selection. Intended behaviour: the selection,
or every visible printing layer when nothing is selected, becomes a transparent PNG
inserted as a new image object above the selection, with the sources kept. Oracles:
SC-0123 and SC-0124, measured against independent golden images and against PNG export.

## Scope and design

- Domain: a pure function that computes the area to convert (visible bounds including
  strokes and effects, plus the margin) and the insertion point, without Angular or
  canvas imports.
- Renderer: reuse the drawing path of PNG export to draw the chosen layers into an
  offscreen canvas at the chosen resolution with a transparent background.
- Editor service: a `rasterize` command that inserts an image layer (a placed picture,
  not a paint layer) in one undo step, and a `rasterizeToPng` entry point that returns
  the PNG without inserting it, for FEAT-0029.
- UI: the Import image button gains a flyout with Import image and Convert to pixel
  image; a dialog with resolution, anti-aliasing and margin; EN and ES catalog entries;
  a new icon file under /assets/icons.
- Contracts: none changed; the result is an image layer of the current format.
- Budgets: the existing image limits of the document; refusal beyond them.

## Divergences from Illustrator

Illustrator's equivalent is Object > Rasterize, which has no default shortcut in CS3, so
none is assigned.

- Illustrator replaces the objects with the raster image; the owner asked to insert the
  image above the selection and keep the sources.
- Illustrator offers a white or transparent background; the owner asked for
  transparency, so the background is always transparent.
- Illustrator's colour model, clipping mask and spot colour options are not offered: the
  editor works in RGB with alpha and the image is always cropped to the art.
- Type optimized anti-aliasing is not offered: the canvas has no hinted type rendering,
  so only art optimized and none are available.
- With nothing selected Illustrator does nothing; the owner asked to convert every layer
  of the document. This plan reads that as every visible printing layer, because hidden
  and guide layers do not print in export either.
- The command lives as a sub-tool of Import image at the owner's request. Proposed for
  parity, pending the owner's confirmation: also list it as Object > Rasterize….

## Work sequence

1. Domain bounds and insertion function with unit tests against hand-computed fixtures.
2. Renderer offscreen drawing with golden image tests (SC-0123 pixel oracle).
3. Editor command, undo, refusal paths and the preview entry point (SC-0124).
4. Flyout, dialog, icons and catalogs, with UI tests; documentation and release notes.

## Failure and migration

No stored format change. A refused conversion leaves the document and history as they
were. Rollback is removing the command; documents that contain converted images keep
them as ordinary image layers.

## Validation and handoff

Automated: packages/domain/tests/rasterize.test.ts (target choice, paint area, pixel grid,
limits, margin frame, in-memory crop and aliasing) and apps/web/tests/rasterize.test.ts (pixels against a golden
image drawn with the canvas API at 150 ppi, placement, group, margin, aliasing, whole document
against PNG export, refusals, the preview entry point, a single readback of the drawing and the shell wiring). Run with
`npx vitest run` on the feat/convert-to-pixel-image branch for 0.10.0; the full suite passed
(143 files, 997 tests). Human review and the paused Sonar analysis are outstanding.
The production build runs in CI; the local Node version is below the Angular CLI minimum.

Unit, golden and UI tests, the documentation checks and the strict quality profile.
Open questions for the owner: the Object > Rasterize entry, and whether hidden layers
should ever be included when nothing is selected.
