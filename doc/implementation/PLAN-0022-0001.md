# Vector import of SVG and ASCII DXF drawings

## Problem and acceptance

Import accepts PNG, JPEG and WebP only, so drawings made elsewhere arrive as pixels
or not at all. Intended behaviour: importing an SVG or an ASCII DXF file produces
editable native layers with their geometry, appearance and grouping, and reports what
the reader could not represent. Oracles: [SC-0091](../sc/SC-0091.md) and
[SC-0092](../sc/SC-0092.md), which measure produced geometry against values computed
by hand, not against the reader's own output.

## Scope and design

- `packages/domain/src/svg-import.ts`: a bounded XML reader and a mapping from svg,
  g, rect, circle, ellipse, line, polyline, polygon, path and text to native layers.
  Path data supports every command including elliptical arcs, converted to cubic
  segments. Transforms compose through groups. Appearance reads fill, stroke,
  stroke-width, opacity and the inline style attribute.
- `packages/domain/src/dxf-import.ts`: a reader for the ASCII group-code format and a
  mapping from LINE, LWPOLYLINE, POLYLINE, CIRCLE, ARC, ELLIPSE, SOLID, POINT and
  TEXT, with layer names kept as group paths and the drawing flipped into screen
  coordinates.
- `apps/web/src/app/editor.service.ts`: one import entry point that dispatches on the
  file, places the result as a group and reports skipped content in the status line.
- Excluded from this slice: PDF and Illustrator, DWG and Canva, for the reasons
  recorded in [ADR-0030](../adr/ADR-0030.md); also SVG `use`, filters, masks,
  gradients, embedded fonts and external images, and DXF blocks, splines, hatches and
  dimensions, each reported as skipped content instead of guessed.
- Budgets: 20 MB per file, 4000 elements and 20000 nodes per import, 150 layers per
  document as before.

## Work sequence

1. SVG reader and mapping with unit tests over hand-computed geometry, then the
   editor entry point and the file dialog.
2. DXF reader and mapping with unit tests over hand-computed geometry, then the same
   entry point.
3. Skipped-content reporting and the interface text in both catalogs.

## Failure and migration

A malformed file raises before anything enters the document, so an import is all or
nothing and a failed one leaves no partial artwork. Imports are ordinary history
steps, so one undo removes them. No document field changes, so files written before
this slice open unchanged and files written after it open in earlier versions. There
is no migration and the rollback is removing the entry point.

## Validation and handoff

Tests: `packages/domain/tests/svg-import.test.ts`,
`packages/domain/tests/dxf-import.test.ts`, `apps/web/tests/vector-import.test.ts`.
Recorded as pending changes on 0.4.0. Visual browser acceptance, strict Sonar
evidence and independent review remain outstanding, and the deferred formats stay
unsupported until their own decision exists.
