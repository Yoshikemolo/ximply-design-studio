# Parametric floor-plan objects and hosted openings

## Problem and acceptance

Create and edit reusable two-dimensional floor-plan objects without manually
rebuilding their paths after every parameter change. Provide wall, door, window and
pillar tools with parameter forms. Door/window leaf widths and opening behavior
must produce visible geometry, not merely stored settings. Hosted openings follow
their wall and produce a cutout. Crossing walls combine visually without destroying
the independently editable source objects.

## Scope and design

Use a bounded registry of trusted procedural geometry functions keyed by native-v2
metadata. Parameters remain declarative data; documents cannot inject executable
functions. Derive vector geometry from parameters for editor display and export.
Retain each source object and its parameters through wall intersection composition.
Use explicit references for hosted openings; keep host validation consistent in the
native parser and authenticated API. The registry is local application code, not a
third-party plugin runtime, external service or BIM implementation.

Wall metadata stores local endpoints and thickness. Openings store width, depth,
leaf widths, operation, swing direction and opening angle; an optional host names a
wall and normalized placement offset. Door leaf counts are bounded to four and
window counts to eight; each leaf width must be positive and their sum must match
the opening width. Opening angles range from 0 to 180 degrees. Lengths are bounded
to 1 through 16384 pixels; hosted openings must fit within the wall segment.
Pillars use rectangular width/depth or equal circular
diameters. Supported transforms regenerate geometry and hosted world placement.
Deleting a host detaches its openings at their latest pose. Moving, resizing or
rotating an opening independently detaches it unless its host is also selected.
Editing the width through procedural properties retains the host and leaf
proportions. Door/window placement near an eligible wall clamps the center to
fit within its length; elsewhere it creates a free opening. Creation defaults
are carried in the current editor session, not persisted as application preferences.

Compatible wall composition joins overlapping walls and shared end faces with
matching paint, stroke width/style, opacity, blend and group membership. Search
within a compatible stack run may pass door/window layers, but ordinary artwork,
hidden walls and incompatible walls stop the run. Render the joined result at the
first member position while retaining all source IDs and independent editing.
Cut each visible hosted opening from its own wall before union, so a crossing wall
is not accidentally removed. Canvas and SVG share this derived materialization.
World-normal physical wall thickness remains meaningful under shear; hosted portal
width stays in physical pixels and portal depth follows transformed host thickness.
If a transformed host becomes too short, detach the opening rather than retain an
invalid fit. Thickness edits retain the wall centerline, and opening-angle edits
retain a free opening's hinge/portal position. Native import also rejects generated
bounds larger than 16384 pixels, even when individual raw parameters are valid.
Existing objects without procedural metadata keep their current rendering behavior.
No new dependency or transport is required; use the existing bounded vector geometry
infrastructure. Ordinary selection, group transforms, appearance and history remain
the interaction boundary wherever supported.

## Acceptance oracles

- Equal parameter sets produce equal finite vector geometry in Canvas and SVG.
  Editing one numeric parameter changes the corresponding geometric extent.
- A wall crossing or shared end face retains source IDs and parameters; editing or
  removing one wall recomputes the join. Ordinary intervening artwork and incompatible
  styles prevent union across their stack position; door/window layers permit it.
- Cutouts affect only their host before union. A crossing wall keeps its material.
  Sheared wall thickness and portal geometry have independent world-space oracles.
- A hosted opening cuts the corresponding wall span, follows host movement and
  responds to its width/offset parameters without drifting from the wall centerline.
- Door swing or sliding representations correspond to the selected mode and leaf
  widths. Window leaf partitions match the configured widths. Invalid widths,
  counts, enum values and nonfinite numbers are rejected before document mutation.
- Creation and parameter edits are atomic undo operations. Cancel creates no
  partial object. Locked objects cannot be indirectly edited through parameter UI.
- Native save/open retains registry keys, complete parameters and valid references.
  API and native parser agree on version, bounds, host and layer restrictions.
- Rendered export retains walls, openings and procedural contours; source parameters
  survive native saves rather than relying on a stale rendered cache.
- Dangling, incompatible or cyclic host references fail predictably. Duplication
  and deletion cannot silently redirect an opening to an unrelated object.

## Failure and migration

Migration: preserve original files before saving new procedural native-v2 metadata.
Older readers may reject or discard parameters and host relations. Use this version
or newer for new saves. SVG/PNG preserve supported visible geometry, not parametric
editing. Reverting application code does not convert native documents backwards.

Bound geometry generation and parameter arrays to prevent unbounded work. Validate
host references before rendering or mutations. Document invalid-reference behavior
and ownership of recomputation explicitly. Reject unsupported combinations rather
than degrading silently. This slice does not claim construction certification,
physical simulation, automatic room topology, BIM/IFC interoperability or a complete
architectural drafting standard.

## Validation and handoff

Shared wall endpoints use offset-line miter intersections to close outside corners.
Joins exceeding ten times the larger half-thickness use a bounded bevel fallback;
free wall endpoints retain flat caps. Independent oracles verify right-angle outer
and inner corners, exact area, unchanged free endpoints and the acute-angle bound.
