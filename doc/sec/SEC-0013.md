# SEC-0013 — Repository operations and remote credentials

Status: Proposed
Owner: Yoshikemolo

## Constraint

- The API service exposes only a closed set of repository operations. User input never
  becomes free command text: Git runs without a shell, with argument lists, validated
  reference names, `--` before paths, and refusal of values that start with a dash.
- Every path is confined to the project directory inside the configured workspace root,
  after resolving symbolic links.
- Repository hooks and executable settings from repository configuration are not run;
  Git uses an isolated configuration.
- Remote credentials live only in the API service and reach Git through a credential
  helper for one operation. They never appear in remote URLs, repository configuration,
  commits, command lines, logs or responses to the browser.
- Content pulled from a remote is untrusted: documents and resources pass the native
  validation and the media checks of SEC-0005 before the editor opens them.
- Every operation has a timeout and a repository size limit; failures leave local
  branches, files and open documents unchanged.

## Verification oracle

SC-0125, SC-0128, SC-0130 and SC-0132, including option injection, traversal, hooks in
a cloned fixture and absence of the credential in every output channel.

## Enforcement

Server-side in the API service, with adversarial integration tests on fixture
repositories. The History tab's controls are user experience only.

## Evidence

Partly implemented in 0.13.0 (SC-0132): the Git runner uses argument lists without a
shell, validated project identifiers and reference names that cannot become options, `--`
before paths, hooks disabled, the system and global configuration ignored, no prompts, a
timeout and a lock per project; resources are named and checked by their hash; the audit
records the operation and outcome, never file content; comments and thumbnails are size
limited. There are no remote credentials yet, since GitHub waits for ADR-0040. Projects are
visible to every user with the change control permission. Human security review is outstanding.
