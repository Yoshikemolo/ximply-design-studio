# SEC-0014 — Licence gating and administration authority

Status: Proposed
Owner: Yoshikemolo

## Constraint

- Advanced endpoints accept only access tokens signed by the configured Keycloak realm
  key, with the expected issuer and audience, an allowed algorithm and no expiry passed.
  Unsigned tokens, other algorithms and keys fetched from token headers are refused.
- The API decides the licence from the token's expiry attribute and permission roles
  against its own clock, on every request. Browser state, request bodies and document
  content cannot grant a licence or a role.
- Admin endpoints require the `xds-admin` role and act on Keycloak through a service
  account limited to managing users of the realm. Its secret and the Keycloak admin
  credentials never reach the browser, logs or repositories.
- Tokens are not logged, not written to documents, exports or repositories, and are sent
  only to the API service and Keycloak.
- Administrative changes are audited with administrator, subject, change and time. New
  and overwritten passwords go straight to Keycloak and are never stored, logged, audited
  or returned.
- An administrator cannot delete, ban or demote their own account, so the realm cannot be
  left without an administrator from the studio.
- A document's owner is the verified subject of the token that saved it, never a value in
  the document or the request.
- The Keycloak login theme is served by Keycloak from the repository and loads nothing from
  other sites.

## Verification oracle

SC-0136, SC-0137, SC-0138 and SC-0139: forged, expired, wrong-issuer, wrong-audience and
`none`-algorithm tokens; expired and permission-less licences; non-admin calls to admin
endpoints; secrets absent from every output channel.

## Enforcement

Server-side in the API service with tests that sign tokens with a test key; the menus
the browser shows are user experience only.

## Evidence

Planned. No implemented security control is claimed by this document.
