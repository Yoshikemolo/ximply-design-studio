# FEAT-0017 — Realtime collaboration presence and following

Status: Planned

## Outcome and scope

SignalR groups, outbox delivery, cursors, avatars and follow state. Implement as a reviewable vertical slice using the functional specification
and the referenced decisions. Expose capability state in the UI and API; do not
advertise a planned action as operational.

## Delivery plan

1. Resolve relevant Proposed ADRs with the owner; inspect current contracts and tests.
2. Define domain invariants and independent SC fixtures before implementation.
3. Implement domain/application behavior, then real and mock adapters, then UI.
4. Add contract/integration tests for every affected boundary and failure path.
5. Update API/schema migrations, documentation, telemetry and capability status.
6. Run functional, security, quality and commit/PR metadata harnesses; prepare review.

## Failure, migration and rollback

Preserve last acknowledged document state and local uncommitted work on failure.
If persistence or plugin payload changes, provide versioned migration fixtures and
forward repair/rollback analysis before merging. Keep old readers safe or explicitly
reject incompatible versions. Disable the new capability flag for rollout failures
without discarding user data. No silent fallback to mocks or unsafe execution.

## Completion evidence

Planned; implementation, tests, performance results and Sonar analysis are absent.
Do not change to Verified until all linked scenarios and module gates have evidence.
