# 0.13.0 — Change control with Git

The History tab gets its panel. It needs advanced mode: a local Keycloak and a licence with
the Change control permission; the API runs the Git command line, now installed in its image.
The online preview has no Keycloak and stays in demo mode. It remains a local preview: the
strict quality gate is paused and outstanding.

Limits: GitHub remotes wait for ADR-0040, so sharing goes through a repository on the server;
a project holds one document; the Settings > Change control category, tags and choosing files
to commit are not implemented; projects are visible to every user with the permission; and
comments on pull requests wait for pull requests, which are not part of this version.

## Breaking changes

None.

## New features

- Make a project of the open document: the API creates a Git repository with a first commit, a clone for each user and a shared repository through which people pull and push. Open a project from the list into a tab that stays linked to it.
- The History tab shows a vertical graph with a lane per branch, branch badges for local and shared branches, HEAD, a row for changes not yet committed and the number of comments of each commit.
- Each commit keeps a thumbnail of the document, shown when the pointer rests on its node or message and in its details.
- Commit details list the message, author, date, identifier, parents and changed files, with comments that anyone on the project can read and write.
- A context menu on each commit, by right-click, the context menu key or Shift+F10: check out, create a branch here, merge, rename, delete, revert, copy the identifier and show details.
- At the foot of the tab: the commit field and Commit, and New branch, Rename, Delete, Merge, Check out, Fetch, Pull, Push, Undo, Redo and Details. Operations that change the document reload it into its tab as one undo step and ask first when it has changes not committed.
- Merges fast-forward or record a merge commit; conflicts are listed per file and resolved with Keep mine or Keep theirs, or the merge is aborted. Undo and redo follow a journal of the operations and refuse to drop commits already shared, offering revert instead.

## Security

- Git runs without a shell, with validated project identifiers and reference names that can never become options, hooks disabled, the system and global configuration ignored, no prompts and a timeout; pictures are stored and checked by their hash; the audit records operations without file content.

## Engineering

- New `/api/vcs` routes, the domain lane layout of the history graph, and the change control facade, with tests against real Git repositories built in a temporary folder.
- Documents are stored canonically with their pictures as resource files named by hash, restored by the API when read.
- Recorded SC-0155 and SC-0156 for thumbnails and comments, the decisions of the slice in PLAN-0031-0001, and comments on pull requests as a future requirement.
