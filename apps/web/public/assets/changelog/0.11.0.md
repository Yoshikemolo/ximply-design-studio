# 0.11.0 — Sign-in, licences and the administration workspace

A minor version that adds advanced mode to the local preview. Everything the editor did
before stays open as a demo; advanced capabilities need a Keycloak sign-in and a licence.
The published preview has no Keycloak, so it runs in demo mode. It remains a local
preview: the strict quality gate is paused and outstanding, and nothing is Verified.

## Breaking changes

None.

## New features

- Sign in and register from the header through Keycloak with the authorization code flow and PKCE; the user menu shows the licence, its tier and permissions, and Sign out.
- A badge after the logo shows Demo, or the tier of a valid licence, in the colour of that tier; the super administrator works without a licence.
- Licences kept in Keycloak with a tier (Free, Pro, Teams, Studio or Enterprise, which grant the same for now), a state (active or suspended), an issue date, an expiry and permissions for AI Tools and change control; the API checks them on every advanced request.
- An administration workspace in the Settings layout, opened from the Admin menu for Users, Roles and permissions, Licences and Documents: shared smart tables with global search, filters after the content of each column, sort buttons in each heading, paging, short dates with the full date, time and zone on hover, ellipsis for long values, first-column selection with bulk actions, and forms in a side panel that slides in from the right.
- Users can be created, edited, activated or deactivated, made administrators, given a new password, banned until a date or permanently with the ban lifted automatically when it ends, and deleted; each shows a status icon, the tier badge, registration, last sign-in and documents saved.
- Documents saved to the server while signed in record their owner; administrators can list, filter and delete them.
- The Keycloak pages of the realm carry the studio wordmark above the form.
- The right column has Properties, AI Tools and History tabs, the header's AI button shows and hides AI Tools, and a separate advanced tools block in the tool rail opens them; the AI Tools and History panels say that they are under development.
- Settings > External tokens keeps each user's own OpenAI API token, encrypted on the server and shown only masked, with its prefix and last four characters, with a connection test that says what it is doing and how it ended.

## Improvements

- Settings and the administration workspace use the room the screen offers.
- The Export button of the header gave way to the AI button; Export stays in File > Export….

## Fixes

- The tooltip of the former Local preview badge showed its catalog key in English; the new badge shows a sentence.
- A request made after the access token expired renews it once and tries again, instead of failing with a message that was easy to miss.

## Security

- The API accepts only access tokens signed by the realm, with the expected issuer and audience and an allowed algorithm, and decides licences on its own clock; administration requires the super administrator and acts through a service account limited to managing realm users.
- Passwords set from the workspace go straight to Keycloak and never appear in answers, logs or the audit; every administrative change is audited.
- External tokens are encrypted at rest with a service key, tied to their user and never returned; without the key the API refuses to store them.

## Engineering

- New API dependencies: PyJWT 2.14.0 with cryptography 46.0.4, cffi 2.0.0 and pycparser 3.0; Keycloak 26.0.8 in the local compose file.
- The local launcher gains start --identity and reset-identity, and scripts/live.py serves the editor with hot reload at http://localhost:8090.
- Recorded the owner's decisions of 2026-09-23 and 2026-09-24: ADR-0012, ADR-0037 (amended for per-user tokens), ADR-0038 and ADR-0039 accepted, ADR-0040 revised, ADR-0041 accepted and amended for the super administrator, FEAT-0032 with SC-0134 to SC-0147, SC-0148, SEC-0014 and the licence tiers as a future requirement.
